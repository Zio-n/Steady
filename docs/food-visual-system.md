# Food logging visuals

**Updated:** 8 November 2026. Phase 0 removes the abandoned generated scene assets and generator. No replacement illustration or AI classification service is required for logging.

Keep existing useful food/meal icons and shared interface assets. Visuals must support quick recognition without replacing the food name, quantity, nutrient basis or editable values. Decorative graphics must not imply a verified product match, serving weight or nutrient accuracy.

The next nutrition design should distinguish supplied values, estimates and unknowns compactly: ordinary value, `≈` value, and `—`. Include accessible names and inspectable assumptions; colour alone is insufficient. Source is separate from certainty, and user-entered guesses remain estimates. These are agreed design rules for later phases, not implemented field-level status in Phase 0.

Calories can stand alone. Apply saved nutrient preferences consistently rather than asking the user to choose nutrients during every log. See the [implementation plan](product-reset-and-semi-rebuild-plan.md#phase-1--relevant-detail-ux-and-data-contracts).
